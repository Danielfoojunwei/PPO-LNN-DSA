# BENCHMARK_SPEC

**Author:** Manus AI  
**Date:** 2026-03-27

## Scope

This document defines the benchmark that now serves as the repository's **primary empirical evidence path**. The benchmark is designed for controlled dynamic spectrum access (DSA) reinforcement learning, using executable environments, real optimization, non-hardcoded outcomes, and persistent result artifacts.

The goal of the benchmark is not to manufacture a universal victory narrative for PPO-LTC-LFM. Instead, the goal is to measure how liquid and recurrent PPO variants behave across several DSA regimes under a fixed and reproducible evaluation protocol.

## Benchmark question

The benchmark asks the following practical question:

> Under controlled DSA environments with stochastic occupancy, interference, varying user load, partial observability, and irregular inter-decision intervals, how do heuristic policies and PPO backbones compare on reward, utilization, collisions, convergence behavior, and training cost?

## Environment family

All benchmark scenarios are built on the executable environment implemented in `empirical/envs.py`. The environment models one learning-controlled transmitter competing with background traffic over a finite channel set. The environment state evolves stochastically, and episodes are generated by simulation logic at runtime rather than by scripted output files.

The observation includes rolling histories of channel-quality proxies, occupancy estimates, interference indicators, sensing uncertainty, and decision interval information. The action is a channel-selection decision. Rewards combine successful access incentives with penalties for collisions and interference.

## Scenario matrix

The benchmark suite includes seven scenario classes.

| Scenario | Purpose | Main stressor |
|---|---|---|
| `stationary` | Reference case for steady dynamics | Stable occupancy statistics |
| `non_stationary` | Tests adaptation to drift | Time-varying occupancy and interference |
| `interference_heavy` | Tests robustness under contention | Elevated interference penalties |
| `varying_users_small` | Tests lighter population changes | Lower competing-user load |
| `varying_users_large` | Tests denser population changes | Higher competing-user load |
| `noisy_partial` | Tests imperfect sensing | Noisy and partially informative observations |
| `variable_dt` | Tests irregular timing | Nonuniform inter-decision intervals |

These scenarios collectively satisfy the requested benchmark coverage for stationary and non-stationary occupancy, interference-heavy settings, varying device counts, partial observability, and timing variability.

## Policy set

The completed benchmark evaluates the following policies.

| Policy | Type | Description |
|---|---|---|
| `random_policy` | Heuristic | Uniform random channel selection |
| `greedy_heuristic` | Heuristic | Occupancy-aware channel choice based on current estimates |
| `ppo_mlp` | RL baseline | Feed-forward PPO baseline |
| `ppo_lstm` | RL baseline | Recurrent PPO with LSTM backbone |
| `ppo_gru` | RL baseline | Recurrent PPO with GRU backbone |
| `ppo_ltc` | RL variant | PPO with liquid time-constant recurrent dynamics |
| `ppo_lfm` | RL variant | PPO with liquid foundation style attention backbone |
| `ppo_ltc_lfm` | RL variant | PPO combining liquid recurrence and liquid foundation style mixing |

The liquid models are therefore benchmarked against both heuristic baselines and strong conventional PPO baselines.

## Federated comparison

Because the repository title retains the hierarchical federated framing, the benchmark also includes a controlled federated comparison for the `non_stationary` scenario using the `ppo_ltc_lfm` model.

| Mode | Description | Communication accounting |
|---|---|---|
| `centralized` | Single global learner on the benchmark task | None |
| `flat_federated` | Synchronous client-to-server FedAvg | Total communicated parameter volume tracked |
| `hierarchical_federated` | Client-to-edge aggregation followed by global aggregation | Multi-hop communication volume tracked |

This federated benchmark is implemented in `empirical/federated.py` and executed by `run_federated_empirical.py`.

## Seed protocol

Every major single-agent result is aggregated over **five seeds**.

| Setting | Seeds |
|---|---|
| Single-agent suite | `7, 19, 23, 41, 89` |
| Federated suite | `7, 19, 23, 41, 89` |

The environment also uses deterministic seed handling with per-instance and per-reset offsets so that episodes vary within a run while remaining reproducible across reruns.

## Metrics

The benchmark records both environment performance and execution-cost metrics.

| Metric | Meaning |
|---|---|
| Mean episode reward | Average return per evaluation episode |
| Reward standard deviation | Across-seed variability of reward |
| Spectrum utilization | Fraction of steps with productive channel use |
| Collision rate | Fraction of steps with harmful contention |
| Background fairness | Fairness proxy among non-learning traffic |
| Mean forward time | Per-step inference proxy |
| Policy entropy | Exploration level during evaluation |
| Wall-clock training time | Runtime cost per completed run |
| Parameter count | Model size in trainable parameters |
| Communication volume | Federated traffic measured in MB |

The core paper-style summaries are written to:

| Artifact | Path |
|---|---|
| Main summary table | `results/aggregate_tables/paper_table_main.csv` |
| Overall ranking | `results/aggregate_tables/overall_model_ranking.csv` |
| LTC/LFM ablations | `results/aggregate_tables/ablation_ltc_lfm.csv` |
| Federated tradeoff table | `results/aggregate_tables/federated_tradeoff_table.csv` |
| Scenario winners | `results/aggregate_tables/scenario_winners.csv` |

## Interpretation standard

The repository should interpret this benchmark under a strict evidence standard.

> Only executed runs saved under `results/` and `results/federated/` count as benchmark evidence.

That means the repository must not present expected outputs, conceptual diagrams, or manually scripted numbers as empirical findings. It may, however, discuss controlled-environment limitations honestly, because the benchmark is a real RL benchmark even though it is not a field deployment on physical radios.

## Minimal reproduction procedure

A minimal reproduction of the current evidence path is:

1. install the pinned packages listed in `requirements.txt`;
2. run `python3.11 run_empirical_suite.py ...` with the documented main configuration;
3. run `python3.11 run_federated_empirical.py ...` with the documented federated configuration;
4. run `python3.11 analyze_empirical_results.py` to regenerate paper-ready tables and plots.

## Benchmark posture

This benchmark is now suitable for **truthful empirical comparison**. It supports nuanced conclusions about scenario-dependent tradeoffs among PPO-MLP, recurrent PPO baselines, and liquid variants, and it supports a narrow but real hierarchical federated comparison with communication accounting. It should be used as a benchmark specification, not as a blanket proof of universal model superiority.
